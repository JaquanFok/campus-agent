# 广财百事通 · 校园生活智能体（Campus Life Agent）

自研 Web 应用：**RAG 检索问答 + AI 审核表白墙**，服务广东财经大学佛山（三水）校区学生。

> **当前阶段**：应用已发布上线，后端与前端可用；**三轮客观评测已完成**（严格通过率 73.1% → 65.4% → 80.8%，75 次真实接口调用全量留存），第 2 轮的指标退化与最终未达 90% 目标均如实记录；知识库内容待在校生逐条校对，真实用户冷启动待开展。仓库中的过程数据与占位数字均如实标注，未验证的结果不会写成既成事实。
> **在线体验**：https://campus-agent-76129.app.workbuddy.host/?sharecode=SKXJBBSXV3
> （请保留 `?sharecode=` 参数，省略该参数会返回 403；这是发布平台对未认证访问的保护，不是应用故障。）

## 为什么做

新生群被重复问题淹没、官方信息零散不可检索——问题不是「没有信息」，而是「信息不可检索」。解法是检索增强 + 严格护栏，而不是让大模型自由发挥：校园场景涉及缴费、门禁、医疗，编造一个数字就是事故。

## 系统架构

- **RAG**：12 个知识单元 → 2-gram 词频检索召回 Top-3 → 知识注入 system 消息 → LLM 流式生成。规模小、零外部依赖、召回可解释可调试（badcase 能直接定位到哪个 gram 没命中）。
- **双 LLM 节点**：问答生成与内容审核各自独立；审核使用独立 system prompt 与结构化 JSON 输出，不复用对话历史，避免多轮对话污染审核规则。
- **云数据库**：PostgreSQL `wall_posts` 表 + RLS 行级安全（仅 `passed` 行可读、匿名可写、1-500 字长度约束）。
- **fail-closed**：审核异常 / 非合法 JSON / 模型不可用一律不上墙，未审内容上墙数恒为 0。

```
用户提问
   ├─ 校园问答 ──→ [2-gram 检索 Top-3] → [系统提示词 + 知识注入 + 护栏] → [流式生成]
   └─ 表白墙投稿 ─→ [独立审核 LLM]
                       ├─ reject   → 拒绝 + 原因（不上墙）
                       ├─ sanitize → 脱敏后写库
                       └─ pass     → 写库
                                      ↓
                              [wall_posts / RLS] → [浏览最新 10 条]
```

## 产品设计

- **护栏 10 条**：问答 G1-G6（不编造 / 敏感事务引导 / 时效提醒 / 越界拒绝 / 情绪安全 / 身份诚实）+ 投稿人身份；表白墙 G7-G9（防挂人防攻击 / 隐私脱敏 / 匿名靠不收集）。
- **AI 审核表白墙**：指名道姓负面内容拒绝、联系方式自动替换为 `[已隐藏]`、正常内容分级放行；审核规则在界面显性公示。传统表白墙死于内容失控，AI 审核把这个品类的最大风险变成产品差异化。
- **匿名写进 schema**：`wall_posts` 刻意不设任何身份字段——匿名由「不收集」实现，而非「承诺保密」，连查询投稿人的可能性都不存在。
- **错误处理与可诊断性**：按 `error.code` 前缀分级提示并附 `requestId`；内置运行环境自检，本地预览时明确告知需从正式链接访问，而不是把鉴权失败伪装成「网络抖动」。

## 商业化路径（v1.3 · 方案设计阶段，未接入）

表白墙是校园内高频、按园区自然聚集的 UGC 场景，可承载场景化推广位。供给分两层：冷启动首批来自同校区已被验证的商家网络（20+ 家校内外商家按 2.5 元/单为触达学生付费），扩展供给来自驾校、校园卡 / 通信运营商、考研 / 考公机构等**校园存量广告预算**——这些广告主本就在投传单、海报与摆摊，产品只是提供一个更可测、可审核的线上位。

广告主按风险分三级：L1 校内档口 / 活动自动审核；L2 驾校 / 校园卡 / 培训机构需资质校验、禁用「保过」「0 元分期」等承诺式话术并强制人工复核；L3 医疗 / 消费贷 / 代考一律拒绝。广告走独立审核链路并强制「推广」标识，与 UGC 分表存储；定向只按园区 / 时段 / 开学季与考期等上下文，不做用户画像（与「匿名靠不收集」的隐私设计兼容）。以推广位占比 ≤12.5%、UGC 投稿量不下降为硬约束，收入优先覆盖 LLM 调用成本。

**状态**：方案设计，未开发、未接入广告主、未产生收入；接入前须补充 8 条评测用例（F1-F8）。完整设计见 `01-产品方案.md` §8。已发布 v1.2 的 26 条评测集 / 10 条护栏 / 三轮 75 次调用数据不因此改变，两者口径互相隔离。

## 评测驱动迭代

- **26 条评测集**：A-D 组 20 条问答（含 4 条护栏陷阱题）+ E 组 6 条表白墙用例，见 `04-评测集.md`。
- **三轮客观复跑**：每轮从正式发布接口抓取 25 条真实返回，共 75 次调用、0 错误，全量留存于 `eval/`；三轮仅系统提示词不同，知识库、检索、用例、模型与判分口径完全一致。

| 轮次 | ✅ | ⚠️ | ❌ | 严格通过率 | 有害投稿拦截 |
|---|---|---|---|---|---|
| 第 1 轮 基线 | 19 | 7 | 0 | 73.1% | 100% |
| 第 2 轮 禁止补充 | 17 | 7 | **2** | **65.4%** ↓ | 100% |
| 第 3 轮 边界精修 | 21 | 5 | 0 | **80.8%** | 100% |

- **指标修订**：原口径 `(✅+⚠️)/26` 把「部分符合」计入通过，会掩盖 Prompt 执行问题；主指标改为**严格通过率 `✅/26`**，⚠️ 单列统计。首次人工打勾的 26/26 = 100% 因开卷判卷未采信。
- **第 2 轮是一次失败的迭代**：收紧「禁止补充」后，7 条显性幻觉（热线号码、线路拼接、服务细节编造）被压下去，但「只澄清不作答」的适用边界未定义，把 A1「热水几点有」、B4「我想寄顺丰」两个明确问句误判为模糊主题词，造成 2 个功能回归。按失败归因精修后才消除。
- **护栏三轮无回退**：C 组 4 条陷阱题全 ✅，E2/E4 有害投稿拦截率 100%，E3 联系方式脱敏正确。
- **目标 90%，实际 80.8%**：残余 5 条 ⚠️ 均为细节级（路径补充 / 澄清边界 / 评价性推断 / 超长 / 情绪安全场景权衡），已归因为「语义约束管不编造、代码约束管格式边界」，列为后续方向。完整方法、归因与数据诚实度声明见 `07-评测报告-三轮迭代.md`。

## 技术说明

前端为单文件 HTML，通过云服务 SDK 调用 LLM 与数据库（keyless，无需自行申请 API Key）。云服务端执行**精确 Origin 校验**，因此本地直接打开 `app/index.html` 只能查看界面，云端功能需从正式发布的链接访问——这是刻意的安全约束，不是缺陷。

## 诚实声明

学生自发维护的**非官方产品**。知识库内容依据公开资料起草（2026-11），尚需在校生逐条校对；热水、门禁、公交等时效性信息一律以学校最新官方通知为准。涉及缴费、资助、医疗、学籍的问题只提供官方渠道指引，不给出结论。评测数据来自真实接口调用并全量留存，未验证的结果（真实用户数、冷启动 badcase）不作为既成事实陈述。
